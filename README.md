# 北斗三号终端测试工具

用一条串口线把北斗三号终端接到电脑，脚本可做两类测试：

- **通信测试**：按固定间隔向**本机地址**发送报文通信申请（`$CCTCQ`），终端入站后由中心回传，
  终端再把收到的报文以 `$BDTCI` 输出。脚本据此判断"发得出去、收得回来"，并实时统计成功率。
- **定位测试**：先发三条设置指令（关 PWI、只开 RMC、设 RMC 频度），再按 RMC 逐帧检查定位状态与经纬度，
  判断"能不能拿到有效定位"，并实时统计成功率。

两类测试可单独跑，也可同时跑。参考文档：《北斗三号民用终端通用数据接口要求（word 修正版 20230117）》。

## 一、运行

本目录下有两个版本，功能完全相同，按有没有 Python 环境二选一：

**免安装版（推荐，不需要装 Python）**：`免安装版\北斗三号终端测试工具.exe`，就一个
11 MB 的文件，双击即用，方便发微信/邮件。启动时先在 **exe 同级目录**解压一个临时目录
（`_MEIxxxx`，退出时自动删除），首次需要几秒；所以 exe 要放在**可写目录**（桌面、U 盘、普通
文件夹都行），不要放 `C:\Program Files` 这类只读位置。记录文件生成在 exe 同级的 `records\` 里。

**安装版（需要 Python 3.7 以上）**：进 `安装版\`，双击 `start.bat`。脚本会自动寻找可用的 Python 3
（优先 `py -3`，其次 PATH 里的 `python`），无需手动装 pyserial——依赖已随 `lib\serial` 一起放在目录里。

也可以命令行运行（在 `安装版\` 目录里）：

```
python bd3_test.py                     # 仅通信（默认）
python bd3_test.py --mode pos          # 仅定位
python bd3_test.py --mode both         # 两者都
```

可选参数：`--port COM9 --baud 115200 --addr 1881210 --data 0123456789ABCDEF --interval 65 --pos-freq 1`。

首次使用建议先勾选**模拟模式**跑一遍，确认界面、判定、统计都正常，再切换到真实串口。

## 二、界面说明

| 区域 | 控件 | 说明 |
| --- | --- | --- |
| 第一行 | 串口 / 刷新 / 波特率 / 打开串口 | 串口列表实时枚举，波特率默认 115200（协议支持 4800~115200），8 数据位、无校验、1 停止位 |
| 第二行 | 本机地址 / 读取地址 / 测试数据 | 地址即北斗卡号（如 1881210）；"读取地址"会发 `$CCICR,0,00` 查询本机 IC 模块信息 |
| 第三行 | 测试模式 / 通信间隔(秒) / RMC频度 | 测试模式三选一：仅通信、仅定位、两者都；通信间隔默认 65 秒；RMC 频度默认 1 秒，最少 1 秒（见第四节说明） |
| 第四行 | 模拟模式 / 开始测试 / 停止测试 / 关闭PWI / 单次PWI | 关闭PWI、单次PWI 是随时可点的设置指令，不必先开始测试 |
| 统计 | 通信一行、定位一行 | 通信：发送 / 成功 / 失败 / 成功率 / 待判定；定位：判定帧数 / 有效帧数 / 无效帧数 / 成功率 |
| 日志 | 收发日志 | 绿色=成功，红色=失败，黄色=警告，蓝色=发送，灰色=普通收发 |

**读取地址**：串口打开后点"读取地址"，脚本发 `$CCICR,0,00`，5 秒内收到 `$BDICP`、`$BDIC` 或 `$BDIBD`
就自动把地址填进输入框；如果地址框是空的，脚本也会从任意 `$BDIBD`/`$BDIC`/`$BDICP` 帧里自动学习本机地址。

**开始测试**前会校验：仅通信/两者都时地址必须是 5~12 位数字，测试数据 1~200 个字符，只允许
ASCII 可打印字符，且不能含 `,` `*` `$`（它们是语句分隔符与起止符）；通信间隔 5~3600 秒；
RMC 频度 1~3600 秒。**关闭串口会自动停止正在跑的测试**。

## 三、通信判定规则

每发送一次 `$CCTCQ` 就是一次判定事务，判定窗口为 `min(60, max(5, 间隔-5))` 秒（间隔 65 秒时为 60 秒）。
窗口内按下列顺序判定：

| 收到的内容 | 判定 |
| --- | --- |
| `$BDTCI` 发信方 = 收信方 = 本机地址，且数据与本次发送完全一致 | **成功** |
| `$BDFKI` 发射情况 = `Y`，窗口结束仍没有匹配的 `$BDTCI` | 失败：入站成功但未收到匹配的回环报文 |
| `$BDFKI` 发射情况 = `N`，原因 = 1（频率未到） | 不立即失败，等设备按"剩余时间"自动重试；窗口内出现 `Y` 且收到匹配 `$BDTCI` 仍记成功，窗口结束没有则失败 |
| `$BDFKI` 发射情况 = `N`，原因 = 2~6（发射抑制/静默/功率未锁定/未检测到 IC/权限不足） | 立即失败，不再等待 |
| 窗口结束一条 `$BDFKI` 都没收到 | 失败：未收到 FKI 发射反馈 |
| 收到 `$BDTCI` 但地址或数据对不上 | 继续等待，窗口结束判失败并注明不匹配内容 |
| 点"停止测试"时该次尚未判定 | 记为"中断"，既不计成功也不计失败 |

成功率 = 成功次数 ÷ 发送次数，实时显示。日志里每次发送、每条 FKI、每条 TCI 与判定结论都带序号，
方便和实测时间线对照。

> 说明：现场日志里出现过"先回 `N`（原因 1 频率未到）、约 11 秒后设备重试回 `Y` 并收到 `$BDTCI`"的情况，
> 所以原因 1 不做立即失败处理，否则会把设备自动重试的成功误判为失败。

## 四、定位测试

选"仅定位"或"两者都"后点开始，脚本依次发三条设置指令：

1. `$CCRMO,PWI,1,0` —— 关闭 PWI 输出（PWI 帧体积大，定位测试时没必要往串口灌）。
2. `$CCRNS,0,0,0,0,1,0,8` —— 打开 RMC 输出、其余定位语句关闭；末位是配置位，固定填 8。
3. `$CCRMO,RMC,2,<频度>` —— 设置 RMC 输出频度，`1` = 每秒一帧，`N` = 每 N 秒一帧。

> **实测说明（2026-11-26）**：`CCRNS` 的 7 个字段依次是 GGA、GSV、GLL、GSA、RMC、ZDA、配置位；
> 末位只接受 `0` 或 `8`，填 1~5、10、15、30、60 时整条指令被丢弃（无 `$ACKOK`、回显退回全 0）——
> **它不控制频度**。频度由 `$CCRMO,RMC,2,N` 控制，实测 N=1/2/3/10 时 RMC 间隔精确为 1/2/3/10 秒，
> 每次设置都回 9 条 `$ACKOK`。另外 N=0 按文档是"单次输出"，但本机实测 12 秒一帧都没有、相当于停止输出，
> 所以界面不接受 0。以上即完整实测记录。

之后每收到一帧 RMC 就判定一次，规则如下：

| RMC 内容 | 判定 |
| --- | --- |
| 定位状态 = `A`，纬度、经度都不为空，模式指示不是 `N` | **有效定位，成功** |
| 定位状态 = `V`（无效定位） | 失败：状态为 V |
| 状态 `A` 但纬度或经度为空 | 失败：经纬度为空 |
| 模式指示 = `N`（无效） | 失败：模式 N |

定位统计的"判定帧数"是收到的 RMC 总数，"有效帧数"是判定成功的帧数，"成功率" = 有效帧数 ÷ 判定帧数。
如果超过 `max(30, 频度×3)` 秒一帧 RMC 都没收到，日志会提示检查终端是否已开启定位输出。

**关闭PWI / 单次PWI** 两个按钮走 RMO 语句（与定位测试开头用的同一条指令，只是参数不同）：

```
关闭PWI:  $CCRMO,PWI,1,0*33    # 打开模式 1 = 关闭指定语句
单次PWI:  $CCRMO,PWI,2,0*30    # 打开模式 2 = 打开指定语句, 频度 0 = 单次输出
```

## 五、发送的帧

`$CCTCQ` 的字段固定为（与现场样例一致）：

```
$CCTCQ,<本机地址>,2,1,2,<测试数据>,0*<校验和>
        收信方    频点 入站确认 编码类别 数据   频度
```

- 频点 2 = S2C（北斗三号民用入站频点）
- 入站确认申请 1 = 不需确认
- 编码类别 2 = 代码（ASCII 字符原样传输，样例 `0123456789ABCDEF` 即按此编码）
- 报文通信频度 0 = 单次发送

校验和为 `$` 与 `*` 之间全部字符按字节异或，两位十六进制大写。例：
`CCTCQ,1881210,2,1,2,0123456789ABCDEF,0` → `*72`，与样例逐字节一致。

## 六、记录文件（CSV）

每次点"开始测试"都会在**程序所在目录**下的 `records\` 子目录里新建两个文件（目录不存在会自动创建；
免安装版在 `免安装版\records\`，安装版在 `安装版\records\`；UTF-8 带 BOM，Excel 直接打开不乱码）：

- `test_record_<年月日>_<时分秒>.csv`：所有判定，一行一条。
- `fail_record_<年月日>_<时分秒>.csv`：只含判定失败的行，格式与主记录完全相同，想单看失败直接开这个。

每完成一次判定就追写并立即落盘，中途关掉程序也不会丢已判定的记录。

| 列 | 含义 |
| --- | --- |
| 序号 | 通信为第几次发送；定位为第几帧 RMC |
| 类型 | 通信 / 定位 |
| 时间 | 发送时刻（通信）或收到 RMC 的时刻（定位） |
| 本机地址 | 通信行的本机地址；定位行留空 |
| 测试数据 | 通信行发出的测试数据；定位行留空 |
| 间隔/频度(秒) | 通信行的发送间隔，定位行的 RMC 频度 |
| 判定 | 成功 / 失败 / 中断 |
| 失败标记 | 失败行标 `★`，成功行为空——在 Excel 里筛这一列就能一眼看到所有失败 |
| 失败原因 | 失败的详细原因（成功时留空） |
| 详情 | 通信行：FKI 反馈与回环报文；定位行：状态、纬度、经度、模式 |
| 用时(秒) | 通信行从发送到判定的耗时；定位行留空 |

通信行的 FKI反馈 形如 `092703 N(1); 092704 Y`，表示先因频率未到失败、1 秒后重试成功。
停止测试时若有一次通信还没判定，也记一行"中断"，不计入成功也不计入失败。

## 七、常见问题

| 现象 | 处理 |
| --- | --- |
| 打开串口失败 | 换一根数据线；确认没有别的软件（串口助手等）占着同一串口；CH340 驱动是否装好 |
| 一直"未收到 FKI 发射反馈" | 终端未入站：看天线、遮蔽、是否已入网；换到窗边或室外再试 |
| FKI 一直 `N` 原因 1 | 发送太密，设备还在等上次的频率窗口；把间隔调大（如 120 秒）再试 |
| FKI 为 `Y` 但没有 `$BDTCI` | 终端入站成功但没收到中心回传，可能是中心侧延迟或该卡的回传通道问题 |
| 成功率显示 `--` | 还没开始判定（分母为 0） |
| 定位一直无 RMC | 终端没收到 `$CCRNS`，或该终端不支持 RNS 指令；看日志里有没有 `设置: $CCRNS,...` 那行，以及终端回的 `$BDRNX` 第 5 个字段是不是 1 |
| 定位全失败、状态一直是 `V` | 天线没看到天空或刚上电还没定位；等几十秒再看，或换到室外 |
| 定位"经纬度为空" | 终端已输出 RMC 但还没解算出位置，属正常的冷启动阶段 |
